# Warp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Texto y archivos PC ⇄ móvil con agujero blanco al recibir, atajo, arrastre de texto y acceso para Laura e Instinct.

**Architecture:** Olimpo gana el tipo `texto` en sus dos bandejas, una ruta de órdenes `warp` y el puente del PC
copia textos con `wl-copy`. En el PC, un CLI `warp` es la única puerta (atajo, arrastre, Laura, órdenes remotas) y
emite `salidas.jsonl`; el shell anima negro al enviar (Portals) y blanco al recibir (WhiteHole).

**Tech Stack:** Python 3.12 + FastAPI + SQLite (Olimpo), Svelte 5 + TS (PWA), Python stdlib (CLI/puente), QML + GLSL/qsb (Quickshell).

**Spec:** `docs/superpowers/specs/2026-11-09-warp-design.md`

## Global Constraints

- Ramas `feat/warp` en LinuxRicing y en Olimpo; se mergean a `main` al terminar.
- `llegadas.jsonl` es contrato fijo: líneas sin `tipo` = archivo (como hasta ahora).
- `texto_max` = 32 KiB (UTF-8). Respuestas de error Olimpo: `{"error":{"codigo","mensaje","detalle"}}`.
- Órdenes remotas: solo `buscar`, `ultimo`, `archivo`; nunca portapapeles/selección/captura.
- Textos de UI en español con tildes. Animaciones QML con `running:` gateado (CLAUDE.md).
- Tests Olimpo: `cd ~/proyectos/olimpo && .venv/bin/python -m pytest tests/tele tests/cli tests/test_rutas_tele.py -q`.
